## Distribution and exact update workflow

Initial distribution is the complete eight-file text bundle at `vendor/fukamu-design-tokens/0.1.0/` in A. Its manifest fixes S and seven payload SHA-256 values; the manifest itself is fixed by the SHA-256 above. Do not use an archive, local `file:` dependency, link, floating branch/tag/ref, CDN, or a hand-edited subset.

From a product repository root, use a fresh clone path and a new version directory:

```bash
git clone https://github.com/fukamu/design-tokens.git /tmp/fukamu-design-tokens-0.1.0-5fcb062
git -C /tmp/fukamu-design-tokens-0.1.0-5fcb062 checkout --detach 5fcb06269607fe3b21184000d286cd7810aa1f47
test "$(git -C /tmp/fukamu-design-tokens-0.1.0-5fcb062 rev-parse HEAD)" = "5fcb06269607fe3b21184000d286cd7810aa1f47"
npm --prefix /tmp/fukamu-design-tokens-0.1.0-5fcb062 ci --ignore-scripts
npm --prefix /tmp/fukamu-design-tokens-0.1.0-5fcb062 run verify:bundle
test ! -e vendor/fukamu-design-tokens/0.1.0
mkdir -p vendor/fukamu-design-tokens/0.1.0
cp -a /tmp/fukamu-design-tokens-0.1.0-5fcb062/vendor/fukamu-design-tokens/0.1.0/. vendor/fukamu-design-tokens/0.1.0/
diff -qr --no-dereference /tmp/fukamu-design-tokens-0.1.0-5fcb062/vendor/fukamu-design-tokens/0.1.0 vendor/fukamu-design-tokens/0.1.0
```

## Approved visual decisions

- Common Light text, default/subtle surface, border, action, focus, and status values follow [Issue #1 option A](https://github.com/fukamu/design-tokens/issues/1).
- Notes warm canvas and decorative surfaces remain Notes-owned.
- Notes Mincho headings remain Notes-owned.
- Success is included.
- Notes dark and all shadows are outside `0.1.0`; Cycle does not gain Dark Mode.
- Code uses the system-font-first fallback stack. Noto Sans JP is only the Figma representative; OS rendering differences remain and no Web Font/CDN is introduced.
- `1rem = 16px`, default border is `1px`, pill radius is `9999px`, and short motion is `160ms`.

## Change requests and rollback

File a missing-token or contract-change request in [fukamu/design-tokens](https://github.com/fukamu/design-tokens/issues) with token meaning, owner, full base SHA, affected products, and evidence. Coordinate same-token work through the common owner; do not make an independent product value source.

Rollback a product by reverting its atomic adoption PR so its prior product mappings and complete prior versioned bundle return together. Never mix files or hashes from two source revisions or contract versions, and never overwrite a released version directory. Keep deprecated public tokens until both product adoption records prove they are unused.
