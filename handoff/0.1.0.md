## 配布方法と厳密な更新手順

初回配布物は、Aの`vendor/fukamu-design-tokens/0.1.0/`にある8ファイルすべてを含むテキストバンドルです。マニフェストにはSと7つのペイロードのSHA-256値が固定され、マニフェスト自体は上記のSHA-256で固定されています。アーカイブ、ローカルの`file:`依存関係、リンク、追従型のブランチ／タグ／ref、CDN、または手作業で編集した一部ファイルは使用しないでください。

プロダクトリポジトリのルートから、新しいクローン先と新しいバージョンディレクトリを使用して、次を実行します。

```bash
git clone https://github.com/fukamu/design-tokens.git /tmp/fukamu-design-tokens-0.1.0-5fcb062
git -C /tmp/fukamu-design-tokens-0.1.0-5fcb062 checkout --detach 5fcb06269607fe3b21184000d286cd7810aa1f47
test "$(git -C /tmp/fukamu-design-tokens-0.1.0-5fcb062 rev-parse HEAD)" = "5fcb06269607fe3b21184000d286cd7810aa1f47"
npm --prefix /tmp/fukamu-design-tokens-0.1.0-5fcb062 ci --ignore-scripts
npm --prefix /tmp/fukamu-design-tokens-0.1.0-5fcb062 run verify:bundle
test ! -e vendor/fukamu-design-tokens/0.1.0
mkdir -p vendor/fukamu-design-tokens/0.1.0
cp -a /tmp/fukamu-design-tokens-0.1.0-5fcb062/vendor/fukamu-design-tokens/0.1.0/. vendor/fukamu-design-tokens/0.1.0/
diff -qr --no-dereference /tmp/fukamu-design-tokens-0.1.0-5fcb062/vendor/fukamu-design-tokens/0.1.0 vendor/fukamu-design-tokens/0.1.0
printf '%s  %s\n' '5c7e8e90873e5581fb70e7676cb5935092fa3a517f46b3a98360c411d7633915' 'vendor/fukamu-design-tokens/0.1.0/manifest.json' | sha256sum -c -
```

プロダクト側のコントラクトテストでは、さらに`manifest.json`を解析し、バージョンが`0.1.0`でSが記録されていることを必須としてください。また、バンドルが記載された7つのペイロードパスとマニフェストだけで構成されることを確認し、各ペイロードのSHA-256を再計算してください。リリース済みのバージョンディレクトリは上書きせず、処理を停止してください。後続のコントラクトでは、新しいバージョンと新たに固定した生成物コミットを使用します。

## 承認済みのビジュアル方針

- 共通Lightのテキスト、default/subtle surface、border、action、focus、statusの値は、[Issue #1の案A](https://github.com/fukamu/design-tokens/issues/1)に従います。
- Notesの暖色系canvasと装飾的なsurfaceは、引き続きNotesが所有します。
- Notesの明朝体見出しは、引き続きNotesが所有します。
- Successを含めます。
- Notesのdarkとすべてのshadowは`0.1.0`の対象外です。CycleにDark Modeは追加しません。
- コードではシステムフォントを優先するフォールバックスタックを使用します。Noto Sans JPはFigma上の代表フォントに限られます。OSによるレンダリング差は残り、Web Font／CDNは導入しません。
- `1rem = 16px`、default borderは`1px`、pill radiusは`9999px`、short motionは`160ms`です。

## 変更要求とロールバック

不足トークンまたはコントラクト変更の要求は、トークンの意味、所有者、完全なbase SHA、影響するプロダクト、エビデンスを添えて[fukamu/design-tokens](https://github.com/fukamu/design-tokens/issues)へ提出してください。同じトークンに関する作業は共通側の所有者を通じて調整し、プロダクトごとに独立した値の情報源を作らないでください。

プロダクトをロールバックするときは、atomicな導入PRをrevertし、それ以前のプロダクト側マッピングとバージョン固定済みバンドル一式を同時に戻してください。異なるソースリビジョンまたはコントラクトバージョンのファイルやhashを混在させず、リリース済みのバージョンディレクトリを上書きしないでください。deprecatedとなった公開トークンは、両プロダクトの導入記録で未使用と証明されるまで維持してください。
