# Repository working agreement

This repository is the single Git source of truth for the shared FUKAMU design-token contract.

## Before changing the contract

1. Read the open Issues and pull requests.
2. Record the owner, affected token paths/files, full base SHA, and affected products in the related Issue.
3. Work in a dedicated branch and worktree based on the agreed revision. Do not share a worktree or overwrite another task's commits.
4. Coordinate changes to the same token meaning or value through the common-token owner. Keep unrelated improvements out of the change.

Issue, branch, worktree, validation, commit, push, and pull-request preparation within an approved task do not require a new permission request. Direct pushes to `main`, merges, auto-merge, npm publication, production deployment, and Figma changes or Library Publish are separate operations and are not authorized by this file.

## Sources and generated files

- `tokens/fukamu.tokens.json` is the only value source.
- `scripts/` owns validation, resolution, and generation behavior.
- `dist/`, `docs/reference/`, and `vendor/fukamu-design-tokens/<version>/` are generated. Never edit them by hand.
- Public tokens must resolve to a literal below `primitive.*`. A consumer must use public paths rather than primitive paths.
- Do not add a second hand-written CSS, JavaScript, Figma, or product-specific value source.
- Contract `0.1.0` is Light only. Shadows and Notes dark mode are outside this contract.

The canonical source revision is an explicit generator input. It must not be derived from or embedded in the commit that contains generated output. Use two commits:

1. Commit the canonical source, scripts, tests, and hand-written documentation without generated output.
2. Pass that first commit's full 40-character SHA to `npm run generate -- --source-revision <sha>`, finalize the HANDOFF SHA, validate, and commit the generated output separately.

## Required validation

Run from a clean worktree:

```text
npm ci --ignore-scripts
npm run check
git diff --check
```

`npm run check` validates the strict DTCG subset, checks generated bytes and bundle hashes, runs positive and negative tests, packs the actual package, and installs it into a temporary consumer. Do not weaken checks, delete assertions, or update generated files without the matching source change.

## Compatibility and history

- Additions, renames/deletions, type/unit changes, and value-only visual changes are different change classes and must be called out in `CHANGELOG.md` and the versioned HANDOFF.
- Do not remove or rename a public token until Cycle and Notes have migrated away from it.
- Both products must adopt the same exact contract version and source revision. A package installation alone is not adoption proof.
- Keep product-owned layout, graph geometry, performance constants, decorative themes, and component behavior out of this common contract.
